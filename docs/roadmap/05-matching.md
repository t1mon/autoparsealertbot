# Матчинг ключевых слов

## Сейчас

Файл: `core/keyword_match.py`

- Нормализация (регистр, ё→е, пунктуация)
- Contains фразы
- Стем (грубый RU) + fuzzy (`SequenceMatcher`, порог 0.82)
- Фраза из 2 слов: достаточно **первого** слова
- Фраза из 3+: достаточно **большинства** слов

## Проблемы

- Ложные срабатывания из‑за мягких правил (первое слово / majority / стем+fuzzy).
- `вк` ≠ `vk` (кириллица/латиница) — короткий токен без fuzzy.
- Нет выбора режима пользователем (строгий / умный).

### Реальные ложные срабатывания (собрать сюда)

| Ключ | Текст (фрагмент) | Почему сработало (гипотеза) | Ожидание |
|------|------------------|----------------------------|----------|
| `работает только вк` | Mail.ru удалили… VK… «продолжают **работать**» | «работать»≈«работает» + мягкие правила фразы | ❌ |
| `лучший vpn` | «но одни из самых **лучших**)» | стем/fuzzy: «лучших»≈«лучший»; для 2 слов достаточно **первого** слова → `vpn` не обязателен | ❌ |
| `лучший vpn` | «это лучший vpn сервис» | фраза / оба слова | ✅ |

Вывод по `лучший vpn`: правило «для 2 слов достаточно первого» слишком агрессивно для ключей вида «прилагательное + vpn». В smart-режиме для 2+ слов требовать **все** значимые слова (или всю фразу), fuzzy — только на опечатки внутри слова, не вместо второго слова.

## Целевые режимы (настройка на пользователя или на ключ)

| Режим | Поведение |
|-------|-----------|
| **strict** | Только нормализованная фраза целиком (contains) |
| **smart** (default) | Стем + опечатки; для фраз — **все** значимые слова; якоря `вк`↔`vk` |
| **loose** | Текущее мягкое большинство (опционально, для экспериментов) |
