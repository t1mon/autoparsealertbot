# База спарсенных совпадений (лиды)

## Зачем

Сейчас при матче по ключу уходит только **алерт в Telegram**. Текст, автор, ссылка в БД **не сохраняются**.

Нужна **база пойманных сообщений** — история, поиск, выгрузка Excel/CSV.  
Автопредложения / продажи — **отдельная тема позже**, в этот документ не входят.

Каталог `TelegramGroup` (база каналов) для этого **не подходит** — там чаты, а не совпадения.

## Целевая модель

### Таблица `leads` (или `matches`)

| Поле | Тип | Назначение |
|------|-----|------------|
| `id` | PK | |
| `owner_user_id` | int | чей парсинг (владелец бота) |
| `author_tg_id` | int \| null | id автора (если удалось получить) |
| `author_username` | str \| null | @username |
| `author_name` | str \| null | display name |
| `chat_id` | int | откуда сообщение |
| `chat_title` | str | |
| `chat_username` | str \| null | |
| `message_id` | int | |
| `message_link` | str \| null | |
| `message_text` | text | текст сообщения |
| `matched_keyword` | str | сработавший ключ |
| `matched_at` | datetime | когда поймали |
| `unique_key` | str | дедуп: `{owner}:{chat_id}:{message_id}` |

Индексы: `(owner_user_id, matched_at DESC)`, `unique_key` UNIQUE.

Поля вроде `status` / `offer_*` **не добавлять** сейчас — появятся, если позже отдельно проектировать офферы.

## Поток при матче

В `process_message`:

1. Собрать sender + метаданные (см. [07-alerts.md](07-alerts.md)).
2. **UPSERT в `leads`**.
3. Отправить алерт владельцу.

Не удалось получить автора → сохранить лид с `author_*=null`, алерт всё равно уходит.

Падение записи в БД не должно ронять алерт (и наоборот — по возможности).

## UX в боте

Подменю **📋 Совпадения** / **Лиды** (в «Мой парсинг» или настройках):

- список с пагинацией (свежие сверху);
- фильтр по ключу / дате (P1);
- карточка: текст, автор, чат, ссылка, ключ;
- выгрузка Excel/CSV за период;
- (P2) удаление старых записей / срок хранения.
